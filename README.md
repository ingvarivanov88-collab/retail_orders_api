# Retail Orders API — сервис автоматизации закупок

Дипломный проект по Python: backend-приложение на Django и Django REST Framework для работы с каталогом товаров, поставщиками, корзиной и заказами.

Реализованы веб-страницы магазина, REST API, административная панель Django, импорт товаров из YAML, а также фоновые задачи на Celery.

## Технологии

- Python 3.12
- Django, Django REST Framework
- PostgreSQL 16
- Redis, Celery
- Docker, Docker Compose

## Требования для запуска

Установите:

1. [Git](https://git-scm.com/downloads) — для получения исходного кода.
2. [Docker Desktop](https://www.docker.com/products/docker-desktop/) либо Docker Engine с плагином Docker Compose — для запуска сервисов.

Во время запуска Docker должен быть включён. Локально устанавливать Python и PostgreSQL не требуется: необходимые сервисы запускаются в контейнерах.

## Запуск проекта через Docker Compose

Откройте терминал (PowerShell, Terminal или терминал IDE) и выполните команды по порядку.

**1. Склонируйте репозиторий:**

```bash
git clone https://github.com/ingvarivanov88-collab/retail_orders_api.git
cd retail_orders_api
```

**2. Соберите образы и запустите контейнеры:**

```bash
docker compose up --build -d
```

Docker Compose запускает четыре сервиса:

- `db` — база данных PostgreSQL;
- `redis` — брокер сообщений для фоновых задач;
- `backend` — Django-приложение;
- `celery` — обработчик фоновых задач.

**3. Примените миграции базы данных:**

```bash
docker compose exec backend python manage.py migrate
```

**4. Создайте администратора:**

```bash
docker compose exec backend python manage.py createsuperuser
```

Введите логин, адрес электронной почты (при необходимости) и пароль по подсказкам в терминале.

**5. Откройте приложение:**

- [Главная страница](http://localhost:8000/)
- [Каталог товаров](http://localhost:8000/catalog/)
- [Административная панель](http://localhost:8000/admin/)
- [API: список товаров](http://localhost:8000/api/products/)

В административной панели войдите с учётными данными, созданными на шаге 4.

## Загрузка тестовых товаров

В репозитории находятся демонстрационные YAML-файлы `shop1.yaml` и `shop_big.yaml`.

1. Запустите проект и создайте суперпользователя по инструкции выше.
2. Откройте [страницу импорта](http://localhost:8000/admin/import/) и авторизуйтесь как администратор, если необходимо.
3. В поле **«Путь к файлу»** введите `shop_big.yaml` (либо `shop1.yaml`).
4. Нажмите **«Запустить импорт»**.
5. Импорт выполняется фоновой задачей Celery. Проверьте результат в [каталоге](http://localhost:8000/catalog/) или в административной панели. Сообщения фонового обработчика можно посмотреть командой:

```bash
docker compose logs -f celery
```

Путь указывается относительно рабочей папки `/app` внутри контейнера, в которую подключён корень проекта.

## Основные маршруты

| Метод | Адрес | Назначение |
| --- | --- | --- |
| GET | `/` | Главная страница (навигация по проекту) |
| GET | `/catalog/` | Веб-каталог |
| GET | `/api/products/` | Список товаров; фильтры `search`, `category`, `shop` |
| POST | `/api/register/` | Регистрация пользователя |
| POST | `/api/login/` | Вход пользователя |
| GET, POST, DELETE | `/api/cart/` | Просмотр, добавление и удаление товаров в корзине |
| GET, POST | `/api/contacts/` | Просмотр и добавление контактов доставки |
| DELETE | `/api/contacts/<contact_id>/` | Удаление контакта доставки |
| GET, POST | `/api/orders/` | Просмотр и оформление заказов |
| POST | `/api/partner/update/` | Обновление прайс-листа поставщика по URL |
| POST | `/api/password_reset/` | Запрос восстановления пароля |
| GET | `/admin/` | Административная панель |
| GET, POST | `/admin/import/` | Импорт YAML для сотрудников |
| GET | `/api/orders/<id>/` | Детали конкретного заказа |

Для работы с корзиной, контактами и заказами требуется авторизация. API можно проверять из браузера через интерфейс Django REST Framework или с помощью Postman.

## Проверка работы после запуска

1. Убедитесь, что открывается `http://localhost:8000/`.
2. Войдите в `http://localhost:8000/admin/` под учётной записью администратора.
3. Импортируйте `shop_big.yaml` через `/admin/import/`.
4. Убедитесь, что товары появились по адресу `/catalog/` и в `/api/products/`.
5. При необходимости проверьте регистрацию, вход, работу корзины и оформление заказа через API.

## Запуск тестов

В проекте есть автоматические тесты для основных сценариев работы API: проверка остатков в корзине, уникальность email при регистрации, содержание корзины, оформление заказа с уменьшением остатков, переключение приёма заказов поставщиком и импорт обоих демонстрационных YAML-файлов.

Тесты запускаются в отдельной тестовой базе данных, реальные данные не затрагиваются.

Команда для запуска: `docker compose exec backend python manage.py test backend -v 2`

Ожидаемый результат в конце вывода: Ran 6 tests, OK

Перед запуском тестов убедитесь, что все контейнеры подняты (`docker compose ps`).

## Полезные команды

**Посмотреть состояние контейнеров:**

```bash
docker compose ps
```

**Посмотреть логи приложения:**

```bash
docker compose logs -f backend
```

**Посмотреть логи фоновых задач:**

```bash
docker compose logs -f celery
```

**Остановить приложение:**

```bash
docker compose down
```

**Повторно запустить контейнеры:**

```bash
docker compose up -d
```

Команда `docker compose down` не удаляет данные PostgreSQL из именованного тома. Не используйте `docker compose down -v`, если хотите сохранить данные.

## Настройка отправки электронной почты

В демонстрационной конфигурации используется консольный email-backend Django. Письма с подтверждениями заказов и уведомлениями выводятся в логи исполняющего задачу контейнера, а не отправляются на реальные почтовые ящики.

Для просмотра писем, сформированных фоновыми задачами, используйте:

```bash
docker compose logs -f celery

```
Адрес администратора, на который уходят накладные по новым заказам, задаётся в `config/settings.py` через параметр `ADMIN_ORDER_EMAIL`. По умолчанию используется `admin@example.com`. При необходимости адрес можно переопределить через переменную окружения `ADMIN_ORDER_EMAIL` в `docker-compose.yml` или `.env`.

## Примечания

- По умолчанию веб-приложение использует порт **8000**, PostgreSQL — **5432**, Redis — **6379**. Указанные порты должны быть свободны на компьютере.
- Настройки в `docker-compose.yml` рассчитаны на локальную демонстрацию и разработку. Для размещения в интернете необходимо изменить секретные параметры и отключить отладочный режим.
- Конфигурация запуска основана на файлах `Dockerfile`, `docker-compose.yml` и `config/settings.py` из этого репозитория.
